# Fusion 360: the CAD of DASH-01

**This folder is the reference CAD of DASH-01.** Everything else in the repo (MuJoCo models, masses)
is derived from it. It is the full export of the Fusion Hub project `Dash-01` on 2026-11-24: every
design, part or assembly, as its own `.f3d` with a `.step` next to it (175 designs), in the Hub
folder tree, plus a `.f3z` for the assemblies that matter.

File names: `<Fusion name>_v<Fusion version>.<ext>`.

## Start here

| File | Content |
| --- | --- |
| [`EXPORT_Xshape/EXPORT_assembly_v8.f3z`](EXPORT_Xshape/) | **Current design** (xshape), standing pose, as exported with ACDC4Robot → [`models/xshape-standing-f8/`](../models/xshape-standing-f8/) |
| [`EXPORT_Achilles_old/EXPORT_assembly_v36.f3z`](EXPORT_Achilles_old/) | v2 design, standing pose → [`models/v2-standing-f36/`](../models/v2-standing-f36/) |
| [`EXPORT_Achilles_old/EXPORT_assembly_homing_v7.f3z`](EXPORT_Achilles_old/) | v2 design, init pose (defines the motor zeros) → [`models/v2-init-f7/`](../models/v2-init-f7/) |
| [`V2/Full_V2_assembly_v81.f3z`](V2/) | Full mechanical v2 robot: 36 designs, with motors (AKE90-8), battery, BMS, DC-DC, screws, bearings, CFRP tubes and their attachments |

`EXPORT_Xshape/EXPORT_assembly_homing_v1.f3z` is an init-pose assembly saved in the xshape folder,
but **it uses the v2 parts** (achilles v7/v4, foot v4, `EXPORT_thigh` v3): it is the v2 init pose. The
xshape init model is generated by `pipeline/repose_init.py`, not exported.

The `EXPORT_*` assemblies are flat (every part directly under the root) and have their closure joints
deleted, as ACDC4Robot needs: see [`../pipeline/README.md`](../pipeline/README.md) §1.

Open a file in Fusion with *File → Open → Open from my computer*: it is uploaded to your Hub as new
designs, with the links between them kept. The `.step` files open in FreeCAD, SolidWorks, Onshape, or
a slicer for printing.

## `.f3d` or `.f3z`?

| Design | Format |
| --- | --- |
| A part, or an assembly whose components are all inside the same file | `.f3d` is complete |
| An assembly that inserts designs from other files (external references, link icon in the browser) | **`.f3z` required**: *File → Export → Type: Fusion Archive Files (\*.f3z)*. An `.f3d` keeps only links to the cloud. |

27 assemblies here have external references (listed at the end of `export_log.txt`). Five have a
`.f3z` (the four `EXPORT_assembly*` and `Full_V2_assembly`); the v2 sub-assemblies (Body, Hip, Cam,
Thigh_right, Achilles, Push_rod_assembly, Foot_right) are complete inside `Full_V2_assembly_v81.f3z`.
For the others, their `.f3d` lacks the linked parts, but those parts are in the folder as separate
files and the `.step` of each assembly has all the geometry.

The Hub's folder download skips Fusion designs, and the Fusion API (so `tools/ExportFolder`) writes
only `.f3d`. Export assemblies by hand as `.f3z`, then check them:
`python fusion/tools/check_f3z.py <file>.f3z`.

### Exporting a whole Hub folder again (`tools/ExportFolder`)

1. Fusion: *Utilities → Scripts and Add-Ins → + → Script or add-in from my device*, pick the
   `tools/ExportFolder` folder.
2. In the Data Panel, open the folder to export, then *Run*. Answer: subfolders, export or only
   check, STEP, output folder.
3. Read the log: failures, and "Assemblies with external references" to export by hand as `.f3z`.

## Rules for this folder

- When the design changes, re-export the changed designs here (new version number in the name, the
  old file can stay or go: git keeps it) and log the change in [`../CHANGELOG.md`](../CHANGELOG.md)
  (date, Fusion version, what changed, why).
- Put the Fusion **version number** in the file names and in the MuJoCo folder names (`f<N>`).
- Fusion files are binary: git cannot diff or merge them. One person edits the CAD at a time.
- Files over 50 MB: GitHub warns; over 100 MB it refuses (the Raspberry Pi STEP is 62 MB).
