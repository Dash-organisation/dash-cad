# Fusion 360: the CAD of DASH-01

**This folder is the reference CAD of DASH-01.** Everything else in the repo (MuJoCo models, masses)
is derived from it. Exported from the Fusion Hub project `Dash-01` on 2026-11-24.

## `.f3d` or `.f3z`?

| Design | Format |
| --- | --- |
| A part, or an assembly whose components are all inside the same file | `.f3d` is complete |
| An assembly that inserts designs from other files (external references, link icon in the browser) | **`.f3z` required**: *File → Export → Type: Fusion Archive Files (\*.f3z)*. An `.f3d` keeps only links to the cloud. |

The Hub's folder download skips Fusion designs, and the Fusion API (so `tools/ExportFolder`) writes
only `.f3d`. The script lists the assemblies that need a `.f3z` at the end of its log; export those by
hand, then run `python fusion/tools/check_f3z.py <file>.f3z`.

### Exporting a whole Hub folder (`tools/ExportFolder`)

1. Fusion: *Utilities → Scripts and Add-Ins → + → Script or add-in from my device*, pick the
   `tools/ExportFolder` folder.
2. In the Data Panel, open the folder to export, then *Run*. Answer: subfolders, export or only
   check, STEP, output folder.
3. Read the log: failures and "Assemblies with external references" (export those by hand as `.f3z`).

## Rules for this folder

- **One current design.** When the design changes, replace the files in `xshape/` (or add a new
  design folder) and log the change in [`../CHANGELOG.md`](../CHANGELOG.md) (date, Fusion version,
  what changed, why). Git keeps the old ones.
- Put the Fusion **version number** in the file names and in the MuJoCo folder names (`f<N>`).
- Fusion files are binary: git cannot diff or merge them. One person edits the CAD at a time.
- Files over 50 MB: GitHub warns; over 100 MB it refuses. Put them in a release instead.
